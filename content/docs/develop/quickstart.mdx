This page completes one representative production read: the 2023 published case-count floor for New York County. The measure id `case_count_floor_2023` is the example in the public observations operation and a measure in the current catalog. County FIPS `36061` is in the lower 48.

You need an HTTPS client. You do not create an account, API key, or SDK project. The client tabs on this page, the workflow guides, and the REST pagination example share one choice in this browser. That choice is curl, Python httpx, R httr2, or TypeScript fetch, and it remains selected after a reload.

## Request

<HttpClientTabs
  path="/v1/observations"
  query="measure_id=case_count_floor_2023&geography_type=county&geography_id=36061&year=2023"
/>

`curl -f` hides error bodies. Drop `-f` when you need to read a problem response.

### Try this request

This playground sends that anonymous GET through the docs site. It adds no API key and does not change the response. The filled example uses New York County, FIPS `36061`, in the lower 48.

<ApiPlayground />

A successful body is a collection:

| Field | Meaning |
| --- | --- |
| `data` | Observation records for this query. An empty array means no row matched. |
| `meta.next_page_token` | Opaque continuation. `null` means this query is exhausted. |
| `meta.response_at` | UTC time when the service built the response. This is not source freshness. |
| `links.self` | Link object field. The contract allows `null`. |

On 12 October 2026 this URL returned HTTP 200, one row, `value_state` `OBSERVED`, a numeric `value`, `unit` `cases`, and `environmental_context` null. The number and `release_id` belong to that release. Read them from your response. A later release can change them.

Read `value` only together with `value_state` and `unit`. `case_count_floor_2023` is a privacy-protected case floor in `cases`. It is a surveillance floor, not a diagnosis, a complete incidence count, or an individual risk estimate.

## States for this request

Read `value` with `value_state` and `unit`. Record the value, unit, period, `release_id`, and `semantic_version` from an observed row. An empty `data` array means no row matched. That is HTTP 200, not HTTP 404. A matching `If-None-Match` on a supported detail resource returns HTTP 304 with an empty body.

Each `value_state`, error `code`, and retry rule is in [Errors and retries](/docs/develop/errors).

`GET /v1/observations?measure_id=case_count_floor_2023&geography_type=county&geography_id=99999&year=2023` returned HTTP 200 with `data: []` on 12 October 2026. An unknown five-digit FIPS can be an empty page. HTTP 404 is the declared not-found status; an empty page means the query succeeded and matched nothing.

The same measure for Adams County, FIPS `08001`, and `year=2023` returned HTTP 200 with `value_state` `MISSING` and `value` null on that date. That row is a gap for the published floor. It is still a successful response.

## Follow provenance

Take `source_id` and `methodology_id` from the observation you received. For this measure on the checked release those ids were `human` and `human_confirmed_probable_case_floor_v1`.

<HttpClientTabs
  requests={[
    { path: "/v1/sources/human" },
    { path: "/v1/methodologies/human_confirmed_probable_case_floor_v1" },
  ]}
/>

Detail routes return `data`. Unknown ids return HTTP 404 `RESOURCE_NOT_FOUND`. A matching `If-None-Match` returns HTTP 304 with an empty body. `GET /v1/sources/human` did that when the previous `ETag` was sent back.
