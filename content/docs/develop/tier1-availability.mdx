Call <Term id="availability">availability</Term> before you render a Tier 1 result.

<Callout title="Interpret with care" type="warn">
  This is surveillance review priority, not Lyme disease risk, predicted
  incidence, probability, clinical risk, or diagnosis. `LOW` is a scored tier.
  `INSUFFICIENT` records input sufficiency, not absence of disease. A null score
  is not zero, and a missing result is not low priority.
</Callout>

Samples are from `https://api.onehealthatlas.org`. Parameters: [priority](/docs/api-reference/counties#getCountyTier1Priority), [availability](/docs/api-reference/counties#checkCountyTier1Availability). Screens: [Evidence, provenance, and uncertainty](/docs/evidence-and-uncertainty).

## When to call each route

<Accordions>
  <Accordion title="Membership and a published model, or not">
    `GET /v1/counties/{fips}/tier1-surveillance-priority/availability`. HTTP
    200. `AVAILABLE` fills `data`. `NO_PUBLISHED_MODEL` nulls `data`. HTTP 404:
    FIPS outside the release.
  </Accordion>
  <Accordion title="The object after the county is supported">
    `GET /v1/counties/{fips}/tier1-surveillance-priority`. HTTP 200 and the
    object. HTTP 404: no current result, not a geography answer.
  </Accordion>
</Accordions>

Use availability when the FIPS comes from outside Atlas. `09001` still fails. The release uses ids such as `09110`. Both routes use HTTP 422 for a bad FIPS, HTTP 429 with `Retry-After`, and HTTP 503 for a failed read. A 503 is not `UNAVAILABLE` and not a tier.

## Read the availability envelope

HTTP 200 uses `availability`, `geography_release_id`, `reason`, and `data`. Samples sent `Cache-Control: public, max-age=60`. `geography_release_id` and `data.release_id` differed here. `generated_at_utc` is batch time, not the request or the observation date. `priority_percentile` is position inside `prediction_batch_version`, not a probability and not comparable across batches. `raw_model_score` is not incidence or a probability. `limitation_ref` is not a URL on this site.

## NOT_ESTIMABLE abstention

`NOT_ESTIMABLE` is published. It is not `UNAVAILABLE` or HTTP 404. Require `AVAILABLE`, null `reason`, and null tier, percentile, and score. `SUFFICIENT` or `INSUFFICIENT` is invalid if any of those three is null. `NOT_ESTIMABLE` is invalid if any is present.

There is no retrieved abstention payload. A sample `GET /v1/atlas/scores` returned 3,144 counties. This was a national API inventory, outside the lower-48-and-DC scope used by the geography guide. Keep that geography scope when you select counties. `AVAILABLE` reports a published result, not product-scope eligibility. See [Geography](/docs/develop/geography). The scores release id matched `geography_release_id` above. Every FIPS returned HTTP 200, `AVAILABLE`, and null `reason`: 651 `SUFFICIENT` (315 `HIGH`, 336 `MEDIUM`) and 2,493 `INSUFFICIENT` (292 `MEDIUM`, 2,201 `LOW`). None was `NOT_ESTIMABLE`. Those counts describe this batch only. If a later batch abstains, do not substitute `LOW`, zero, or "no disease." Keep version, release, batch, policy, `generated_at_utc`, and `limitation_ref`.

## UNAVAILABLE and NO_PUBLISHED_MODEL

`UNAVAILABLE` is HTTP 200 after geography and the Tier 1 projection are both read. `reason` is `NO_PUBLISHED_MODEL`, `data` is null, and `geography_release_id` remains. Null stays null. This is not `NOT_ESTIMABLE`, HTTP 404, or HTTP 503.

There is no retrieved `NO_PUBLISHED_MODEL` payload. That inventory had no `UNAVAILABLE` body. Do not invent a county. A null `data` value is not low priority.

## Handle a FIPS outside the release

`GET /v1/counties/99999/tier1-surveillance-priority/availability` returned HTTP 404 `application/problem+json` and a private cache directive. `00000` and `09001` matched this status and detail.

```json
{
  "type": "https://onehealthatlas.org/problems/resource-not-found",
  "title": "Invalid public query",
  "status": 404,
  "detail": "County is not in the current geography release.",
  "instance": "/v1/counties/99999/tier1-surveillance-priority/availability",
  "request_id": "91af7989-a353-48e6-af9b-812727c66747",
  "code": "RESOURCE_NOT_FOUND",
  "errors": null
}
```

`status` 404 and `code` `RESOURCE_NOT_FOUND` mean the county is outside the release, not that a tier was assigned. `request_id` changes on the next call.

A non-five-digit path skips that check. `GET /v1/counties/0911/tier1-surveillance-priority/availability` returned HTTP 422, detail `One or more request values are invalid.`, and an `errors` pattern failure on `fips`. Send `09110`, not `9110`.

The priority route does not answer geography. `GET /v1/counties/99999/tier1-surveillance-priority` returned HTTP 404 and no `code`:

```json
{
  "type": "https://onehealthatlas.org/problems/http-404",
  "title": "Not found",
  "status": 404,
  "detail": "No current Tier 1 county result",
  "instance": "/v1/counties/99999/tier1-surveillance-priority",
  "request_id": "c57750de-fca5-4ed2-8bbb-2d45f422cf97",
  "errors": null
}
```

HTTP 404 is also used when no published result exists. This sample had no such county. Do not treat that 404 as a failed geography check or as `LOW`.

## Keep these states apart

| State | What to do |
| --- | --- |
| `SUFFICIENT` `HIGH` | Do not say: The county is high risk, or the percentile is a probability |
| `INSUFFICIENT` `LOW` | Do not say: Safe county, placeholder zero, or absence |
| `NOT_ESTIMABLE` | Do not say: Low priority, or no disease |
| `NO_PUBLISHED_MODEL` | Do not say: Null data is zero or a low tier |
| Availability 404 | Do not say: No Lyme activity |
| Priority 404 | Do not say: Geography failed, or the county is low priority |
| HTTP 422 | Do not say: The county was looked up and found missing |
| HTTP 503 | Do not say: The failure is an evidence tier |
