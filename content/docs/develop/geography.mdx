Atlas joins public records on geography identity. Identity is a type plus an id. It is independent of map polygons.

## Identity

`GeographyIdentity` has two required fields:

| Field | Values |
| --- | --- |
| `geography_type` | `county` or `state` |
| `geography_id` | <Term id="fips">FIPS</Term> string with leading zeros. Five digits for a county. Two digits for a state |

`GeographyType` does not include tracts, ZCTAs, or other units. `geography_type=tract` on the observations query returned HTTP 400 `INVALID_REQUEST`.

These guides use the lower 48 states and the District of Columbia. Keep FIPS in a string so a leading zero survives JSON and CSV.

| Example id | Place | Role in these guides |
| --- | --- | --- |
| `36061` | New York County, New York | Quickstart observation |
| `08001` | Adams County, Colorado | Comparison row that can be `MISSING` while another county is `OBSERVED` |
| `09110` | Capitol Planning Region, Connecticut | Selected land-cover geography named by that measure |
| `51013` | Arlington County, Virginia | The other selected land-cover geography named by that measure |

`09110` is a Connecticut planning-region geography. The land-cover measure limitations say it has no historical Connecticut county crosswalk. Use the FIPS the measure names. Do not rewrite it to an older county id.

## Observations are county queries

`GET /v1/observations` requires `geography_type=county` and 1 to 500 `geography_id` values. Repeat the parameter once per county. The service orders rows by measure id, county FIPS, period start, and observation id. It does not accept a caller sort.

A five-digit id that matches no row can still return HTTP 200 and `data: []`. That happened for `geography_id=99999` with `case_count_floor_2023` and `year=2023`. Empty is a successful query with no observation.

## Typed geography identity

The public contract declares:

```text
GET /v1/geographies/{geography_type}/{geography_id}
```

<EndpointDeliveryBadge />

The operation summary is "Get geography identity (delivery pending)". A county or state FIPS with the right shape returns HTTP `200` and `application/json`. While canonical identity delivery is unpublished, that body is `GeographyUnavailable`. Callers do not receive a `Geography` label or parent from this route. Responses use `Cache-Control: no-store`.

`availability` is `UNAVAILABLE`. That names a publication boundary: this capability has not published canonical geography metadata. It does not say the county has no disease, no ticks, or no observations.

`reason` is `CANONICAL_GEOGRAPHY_UNPUBLISHED`.

`data` is `null`. The route does not fill in a geography resource.

`geography` echoes the requested identity. The identity is validated for shape only. A five-digit county id or a two-digit state id is enough. This response does not assert membership in the current release.

`limitations` is a non-empty list of publication and representation boundaries.

The `200` schema is a union of `ResourceEnvelope_Geography_` and `GeographyUnavailable`. The operation also documents `400`, `404` `RESOURCE_NOT_FOUND`, `413`, `414`, and `429` with `Retry-After`.

On 25 October 2026, `GET /v1/geographies/county/08001` returned HTTP 200. The origin status was 200. The JSON body was:

```json
{
  "availability": "UNAVAILABLE",
  "reason": "CANONICAL_GEOGRAPHY_UNPUBLISHED",
  "data": null,
  "geography": {
    "geography_type": "county",
    "geography_id": "08001"
  },
  "limitations": [
    "Canonical geography identity delivery is not published by this API capability.",
    "The requested identity is validated for shape only; membership in the current release is not asserted (use the county availability route for that). No canonical, display, or analysis geometry is returned or inferred."
  ]
}
```

The badge records that dated production check. It is not a live health indicator.

## County membership

The identity route does not say whether a county is in the governed directory. Ask that with the county availability route:

```text
GET /v1/geographies/{geography_type}/{geography_id}/availability
```

That route is counties only. A state id returns HTTP `400`. The operation is [Check canonical county geography publication availability](/docs/api-reference/geographies/canonicalGeographyAvailability).

## Polygons are a different resource

The geography identity route does not return a polygon. When you need a county outline, call the display-geometry route:

```text
GET /v1/atlas/geometry
```

<DisplayGeometryCurl />

On 18 October 2026 that request returned HTTP 200 `application/geo+json`. The response used `Cache-Control: public, max-age=31536000, immutable` and an `ETag`. The body was a GeoJSON FeatureCollection of 3,144 features. Each feature carried `fips` and a polygon. `36061` and `11001` were in the collection. That count is a national display inventory. These guides still use the lower 48 states and the District of Columbia. The operation is [Get county display geometry](/docs/api-reference/atlas#getAtlasGeometry).

The contract describes that response as display GeoJSON, EPSG:4326, with an immutable cache and an `ETag`. It is a generalized display boundary for maps. It is not the FIPS join key and it is not the analysis geometry used to build measures. `environmental_context.geometry_version`, when that object is present, names analysis geometry and still contains no polygons.

County analytics, including `in_contiguous_tick_scope`, are on `GET /v1/counties/{fips}` together with release metadata. That route is separate from `GET /v1/observations`. Its `404` body can omit `code`. Score query parameters on that route belong to the legacy county operation; they are not observation filters.

## State ids

`state` is a legal `geography_type` for geography identity. The observations query documented here asks for county FIPS. The measure `state_unallocated_records_2023` uses state geography semantics and keeps records that are not assigned to a county. Read that measure's own definition before treating it as a county total. County-linked values and state-unallocated records stay separate.
