Epidemiologists, REST clients, and MCP clients use this page to see how a governed source becomes canonical Atlas evidence, and which of that design is released today.

Public-health evidence arrives in different systems, formats, vintages, terminologies, geographies, and publication processes. Atlas is designed so a new governed source can be added without a separate data model for every source.

The intended path is:

`source system → source-specific adapter → terminology/semantic mapping → canonical Atlas evidence and provenance → REST API / MCP / product workflows`

<Callout title="Interpret with care" type="warn">
  A shared model keeps provenance and uncertainty attached. It is not a claim
  that two sources measured the same thing, covered the same people or ticks, or
  can be compared without their limitations.
</Callout>

## What is released and what is intent

Use the same status labels as [current capabilities](/docs/current-capabilities).

| Capability | Status | What you can rely on |
| --- | --- | --- |
| Open public evidence in the current release | Available now | Observations, sources, and methodologies on `/v1`. See [API, MCP, and access](/docs/api-mcp-and-access), the [API reference](/docs/api-reference), and [evidence, provenance, and uncertainty](/docs/evidence-and-uncertainty). |
| Source-specific adapters for later governed sources | Planned | One adapter per source. Patterns include CSV, XLSX, an API, a scientific file, and other governed inputs. A file type is not a released source. |
| CDC Lyme/TBRD Message Mapping Guide (MMG) and PHIN VADS | Planned | Direction for surveillance concepts where a mapping uses them. Not a certification. |
| USCDI, FHIR R4 / US Core, Bulk FHIR, and LOINC | Planned | Direction for a future authorized clinical or laboratory source. Not a released feed. |
| Live EHR connectivity, TEFCA, patient-level data, PHI, or production clinical-laboratory ingestion | Not supported | Naming a standard does not grant access, authority, certification, or a connection. |
| Bounded anonymous MCP evidence reads | Available now | `atlas_discover_indicators`, `atlas_get_county_profile`, and `atlas_get_evidence_provenance` return public evidence. `atlas_resolve_geographies` resolves county identity and does not establish that evidence exists. See the [public evidence tool contract](https://github.com/Caraway-Labs/one-health-lyme-gap-atlas-mcp/blob/d26ef2b72a2f9203a26ff45a3ad13f0f2ac104c9/docs/public-evidence-tools.md). |

The current MVP is open-data-first. Each result still names its source. This page does not publish a second source catalog.

`server_status` and `atlas_smoke_test` are not in the current production tool list. The September 2026 receipt that covered smoke tools only is historical. See [MCP clients](/docs/develop/mcp-clients) and [ADR 0003](https://github.com/Caraway-Labs/one-health-lyme-gap-atlas-mcp/blob/d26ef2b72a2f9203a26ff45a3ad13f0f2ac104c9/docs/adr/0003-public-evidence-tools.md). Those tools are not a live EHR, TEFCA, patient-level, PHI, or production clinical-laboratory connection.

## How a source becomes Atlas evidence

1. **Source system.** The publisher's system, file, or feed.
2. **Source-specific adapter.** A governed adapter reads that source. It is not a universal parser and not permission to collect the source.
3. **Terminology and semantic mapping.** A mapping annotates source meaning. It keeps the original source identity, version, and limitations.
4. **Canonical Atlas evidence and provenance.** Readers receive governed observations, sources, and methodologies, with provenance attached.
5. **REST API, MCP, and product workflows.** Consumers use that canonical evidence where the public contract supports it.

A county value can remain missing, suppressed, unavailable, or uncertain after normalization. Transport format and source authorization are separate. Support for a format, or alignment with a named standard, is not access, legal authority, interoperability certification, or a live connection. Bulk FHIR is a possible future transport. It is not a connection Atlas operates today.

## What normalization preserves

Heterogeneous records are normalized into stable Atlas concepts. The public contract does not expose a different downstream model for every source. These facts stay with the evidence:

| Preserved fact | What it answers |
| --- | --- |
| Source and publisher | Who produced or published the input. |
| Dataset, version, and vintage | Which release of that dataset the value came from. |
| Geography | Which governed county or state the value describes. |
| Observation period | The inclusive period and grain, distinct from when Atlas loaded the release. |
| Units and denominators | The measure's unit and any governed denominator. A missing denominator is not invented. |
| Transformation and method | The methodology and version that produced the Atlas value. |
| Missing, suppressed, unavailable, and uncertain meaning | Whether a number was published, withheld, absent, or too limited to treat as a confident result. |
| Quality and limitations | Coverage, comparability, and other governed limits. |
| Lineage and provenance | How the row traces to the source record and the Atlas release. |

Field names and types for the current release live in the public OpenAPI contract. Read them in [Provenance and evidence](/docs/develop/provenance), the generated [provenance reference](/docs/api-reference/provenance), [observations](/docs/api-reference/observations), and the generated [schemas](/docs/api-reference/schemas). This page does not copy those schemas.

Product geography for the developer guides is the lower 48 states and the District of Columbia. See [Geography](/docs/develop/geography).

## Missing, suppressed, unavailable, and uncertain

Normalization keeps these states distinct. Do not collapse them into zero, and do not collapse them into one another.

| State | What remains true after normalization |
| --- | --- |
| **Observed** | The source published a value or status for the stated geography and period. The public code is `OBSERVED`. |
| **Zero** | The source published a numeric zero. The public code is `ZERO`. Coverage and method still bound that zero. |
| **Missing** | No governed value was published for that geography and period. The public code is `MISSING`. Missing is not zero and not biological absence. |
| **Suppressed** | The publisher withheld the value, including for privacy or a reporting rule. The public code is `SUPPRESSED`. Do not reconstruct a precise count. |
| **Unavailable** | The source, field, geography, or period is not in this release. The public code is `UNAVAILABLE`. Unavailable is an evidence gap. |
| **No county-linked record** | No county-linked row is in the release. The public code is `NO_COUNTY_LINKED_RECORD`. The contract treats this as not evidence of absence. |
| **Uncertain** | A governed limitation, sparse coverage, a stale vintage, or disagreement limits how far the value can be read. Uncertainty stays attached as that limitation. It is not rewritten into a confident number, and it is not an extra public value-state code. |

`MISSING`, `SUPPRESSED`, and `UNAVAILABLE` require a null value in the public contract. A null value is not zero. The signed-in workspace shows **Available**, **Limited**, and **Unavailable** after a successful response. **Suppressed** stays visible as suppression. Loading and request failures are not evidence states.

Plain-language rules and workspace labels are in [Evidence, provenance, and uncertainty](/docs/evidence-and-uncertainty). The contract table, in enum order, is in [Indicators, measures, and observations](/docs/develop/resources). Release time, source period, and methodology version stay separate in [Releases and methodology labels](/docs/releases-and-methodology).

## Standards, where they apply

These standards are selected directions for particular sources. They are not a universal data standard, and they are not a requirement that every future source must be FHIR. Naming one does not certify a feed or open a live connection.

| Standard | Where it applies |
| --- | --- |
| CDC Lyme/TBRD Message Mapping Guide (MMG) and PHIN VADS | Surveillance concepts, when a governed mapping uses them. |
| USCDI | A future clinical or laboratory data-element anchor. Not in the current release. |
| FHIR R4 and US Core | Future authorized clinical or laboratory semantics, when that source uses them. |
| Bulk FHIR | A possible authorized population-scale transport. Not permission, and not an operating feed. |
| LOINC | Laboratory terminology for a source that already uses it. Current open-data measures are not claimed as LOINC-coded. |

A mapping annotates source meaning. The observation still carries its source, dataset, vintage, geography, period, method, value state, and limitations.

## What Web, REST, and MCP consume

Where the public contract already presents canonical evidence, use that governed contract rather than a source-specific schema.

| Consumer | Authority | Current boundary |
| --- | --- | --- |
| Web product | Released experience. Provenance stays beside the result. | Current open public evidence. The [professional workspace](/docs/professional-workspace) adds no private clinical feed. |
| REST API | Public OpenAPI document. The [API reference](/docs/api-reference) links the raw [OpenAPI schema](https://api.onehealthatlas.org/openapi.json). | Anonymous reads of indicators, measures, observations, sources, and methodologies. Legacy county and state analytics are a separate route family in the [developer overview](/docs/develop). |
| MCP | The [public evidence tool contract](https://github.com/Caraway-Labs/one-health-lyme-gap-atlas-mcp/blob/d26ef2b72a2f9203a26ff45a3ad13f0f2ac104c9/docs/public-evidence-tools.md) and its tests in the [Atlas MCP repository](https://github.com/Caraway-Labs/one-health-lyme-gap-atlas-mcp). | Bounded anonymous read-only surface. The three evidence tools return canonical public evidence. `atlas_resolve_geographies` returns county identity only. |

Semantic and provenance meaning stays with the observation, source, and methodology resources. This site does not maintain a second HTTP schema, a second MCP tool list, or a second semantic contract.
